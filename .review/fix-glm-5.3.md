# Implementation Review — Issue #50 Resume Downloads (`fix.diff`)

**Overall verdict: APPROVE-WITH-CHANGES**

The core mechanism is sound and well-pinned: journal validation is comprehensive and fail-safe (any mismatch discards both files), the resume math is byte-correct, the 206/short-stream checks close a real pre-existing corruption hole, and the test suite (unit matrix + worker-level + wire-level e2e) genuinely pins the contract with the determinism fixes from the plan review folded in. Two findings require changes before merge: a false lock-scope comment covering an actually-violated pinned discipline (one-line fix), and stale contract text in `src/AGENTS.md` §6 that now contradicts both the code and the updated root `AGENTS.md`.

## Checklist answers

**1. Correctness — OK.** `ResumeJournal::validate` (src/download/journal.rs:150-202) covers url/total_size/chunk_size/offsets-length/per-offset-bounds/on-disk-length/sha256/etag, all pinned in `journal_tests::validate_matrix_rejects_every_mismatch`; I found no bypass that resumes into wrong bytes. Crash direction is under-report at the application level (data `write_all` completes before `record`; completion record only after `flush`+`sync_all`, chunked.rs:741-743); the sole over-report window is power-loss vs page cache on *mid-chunk* offsets, which is explicitly documented and accepted (journal.rs:37-40) — see residual risks. No deadlock is possible (progress→journal is the allowed direction; journal remains a leaf), but the sync write+fsync+rename now runs under the progress lock, stalling sibling chunk tasks' progress updates and HUD/CLI renders — exactly the stall the plan §3.1 pinned against. Finding 1.

## Findings

1. **[MAJOR] src/download/chunked.rs:716 (with 681, 712-715)** — `journal.record` runs inside the `progress` lock scope. The guard bound at line 681 lives to the end of the `if elapsed >= interval_secs` block; there is no `drop(prog)` before line 716. No deadlock (journal stays a terminal leaf; nothing acquires journal→progress; no await under the journal mutex), but the sync journal save (write+fsync+rename, up to ~1/s per active chunk) executes while holding the render mutex — the exact stall the plan §3.1, journal.rs:45-47, and the root AGENTS.md entry all forbid, and the comment at 712-715 is factually false. Fix: `drop(prog);` before `journal.record(...)` (one line) — the completion-record call site (743) is already clean.

2. **[MAJOR] src/AGENTS.md:73,75** — §6 still documents the pre-#50 contract (unconditional `.incomplete` restart/delete), contradicting the diff's own root AGENTS.md update and the implementation. This repo's docs-truth regime (docs_guards) treats agent-navigation docs as contract; update §6 in this change.

3. **[MINOR] README.md:499** — exit-code-130 row says "restart from scratch on the next run"; the message it documents (src/cli/download_cmd.rs:155) now says "RESUME from their partial download". Update the row.

4. **[MINOR] src/download/mod.rs:262-279 + 362-364** — already-exists leak: when `final` exists together with `.incomplete`+journal, phase 1 keeps the partials and `handle_existing_file` returns AlreadyExists without cleaning them, leaving a full-size `.incomplete` + journal next to a complete file until a TUI delete or manual removal (old code's unconditional prepare-time delete prevented this). Suggest removing stale partials in the already-exists branch.

5. **[MINOR] src/download/journal.rs:33-40 (documented residual)** — mid-chunk offsets are journaled with an fsynced sidecar while the data is only in the OS page cache; a power loss can make the journal over-report durable bytes, and non-LFS files without an ETag have no verification backstop (completed chunks are safe; LFS is backstopped). The plan accepts this; a follow-up could `sync_all` the shared data file once per `FLUSH_INTERVAL` before saving.

6. **[NIT] src/download/journal.rs:238** — `record` evaluates `chunk_len(chunk_id)` before the `get_mut` bounds check; an out-of-range id would underflow-panic (debug) instead of taking the intended early return. Unreachable from current callers; reorder.

7. **[NIT] src/download/journal.rs:102-112** — `save` uses a fixed `.tmp` name + plain `std::fs::rename`, without the Windows-aware rename-with-retry twin the registry uses; a failed save is silently swallowed (safe — stale journal under-reports) and a crash mid-save leaves a `.state.json.tmp` orphan nothing cleans.

8. **[NIT] src/ui/app/downloads.rs:330** — duplicates the `.state.json` naming scheme as a magic string rather than a shared helper (`journal::journal_path` is `pub(super)`); a future rename drifts the TUI silently.

9. **[NIT] tests/resume.rs:391-436** — scenario 5 changes ETag and sha/content together, so the e2e does not isolate the etag discard rule (unit matrix does).

10. **[NIT] src/download/mod.rs:14-20** — facade "Layout" doc still says "one private submodule" and lists only `chunked`; `journal` is undocumented there.

Approve with changes: the resume design is correctly implemented and genuinely pinned by tests — validation is fail-safe with no bypass found, the wire-level e2e proves completed ranges are never re-requested across retries and runs, and the 206/short-stream hardening fixes a latent corruption bug beyond the issue's scope. Required before merge: fix the progress-lock-scope violation at the mid-stream `journal.record` call site (and its three now-false doc claims), and reconcile `src/AGENTS.md` §6 (plus README:499) with the new keep-and-resume contract.
